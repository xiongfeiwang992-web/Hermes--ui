# 实现状态与外部依赖

本文件记录 MASTER-2.1 在自研代码中的交付状态。这里的“完成”指本地业务闭环可录入、查询、流转、审批、消息、审计和自动验收；不代表已经购买或开通第三方商业服务。

## 已完成：门店主链路

- 自有账号、四角色、门店和数据范围
- 房源、客源、公私客、保密盘、电话脱敏
- 跟进、待跟进、带看
- 成交提交、审批、驳回
- 收款、意向金、提成
- 工作台、站内消息、审计日志、经营报表

## 已完成：盘客和交易深化

- 自建楼盘字典
- 钥匙登记、借还、作废
- 实勘、空看、验真
- 多联系人、客源合并、房源匹配
- 可配置自动掉公，默认关闭
- 合同、贷款、缴税、过户、交房节点
- 房源委托、锁定、合作、媒体、拍卖和包销记录
- 贷款、成交投诉、更名和资料清单

## 已完成：扩展业务通用流程层

| 业务域 | 本地能力 |
|---|---|
| 新房 | 项目、报备、到场、分销公司、销售报告 |
| 财务 | 收入、支出、报销、资产、凭证、薪酬 |
| 人事 | 岗位职级、调动、离职交接、考勤、请假、招聘、人事合同、工资条 |
| 办公 | 公告、知识、考试、活动、会签、票据、总结、同事圈、来电记录 |
| 营销 | 官网内容、在线委托、商机、营销活动 |
| 租赁托管 | 托管物业、租约、租金账单、维修、保洁 |
| 客关 | 投诉、诉讼、满意度问卷、回访 |
| 绩效 | 积分、管理奖、利润分红、业绩目标 |

上述扩展模块统一提供持久化、状态机、审批、权限、消息与审计，避免只做静态菜单或假数据。它们是可继续配置字段和规则的本地流程层，并不等同于原厂每个专项模块多年积累的全部行业字段、第三方渠道和财务会计细则。

当前已进一步专项落地的细节包括：房源物业类型/交易模式与查重提示、陪看人多选、成交本地附件、审计筛选导出。供应商级总账、自动更新分发、移动端独立客户端等仍须单独产品化和上线验收，不能仅凭通用流程记录宣称完成。

后续专项规则已补充：用户偏好与水印、可配置数据字典、个人持盘上限、房源锁定、保密客、成交必录和贷款字段、店长管理奖、阶梯提成、退款净额、自有合同模板与本地签署确认。这里的本地签署确认不具备第三方 CA 法律电子签能力。

强制跟进与非接盘人带看提醒已落地：管理员可在业务参数中开关「经纪人查看电话前强制写跟进」与「非接盘人带看提醒接盘人」。启用强制跟进后，经纪人即便具备查看权限也先看到脱敏电话，须通过 `contact.reveal`（写跟进）解锁；店长与管理员不受此限制。非接盘人登记带看时，默认向房源接盘人发送站内消息；可关闭。该能力是本地跟进留痕与提醒，不提供运营商真隐号拨打或通话录音。

盘源图片与业主相关盘已深化：房源附件支持软删除且必须填写原因并写入审计；生效委托关联附件禁止删除；删除封面附件时同步清空 `cover_image`。`house.relatedByOwner` 按业主电话聚合当前可见相关盘。工作台只读展示公司名、门店数与在职员工数。

出纳到账确认已落地：财务/管理员登记佣金收款后进入 `pending`，不计入已收；须 `payment.confirm` 后才计入净已收并通知经纪人。支持带原因驳回；退款仍仅针对已确认净额即时登记。意向金冲抵继续直接记已确认收款。该能力是本地出纳确认流，不对接银行回单自动核销。

消息订阅设置已落地：用户可按频道开关收付款、跟进带看、房源协作、办公、租赁、客关、营销、绩效、人事、新房等站内消息；成交审批频道锁定必开。关闭后 `createMessage` 不再写入对应用户收件箱，默认全部开启。该能力仅为本地收件偏好，不提供短信/推送/邮件外发。

房贷计算器已落地：支持按 LPR+基点或直接年利率测算等额本息与等额本金，输出首末月供、利息合计与分期计划。纯本地数学工具，区别于成交按揭审批流程，不连接银行或征信接口。

经营报表分析已加深：成交热点按小区/总价段/面积段聚合本月已审批成交并可导出；盘源属性按租售、物业类型与价格段统计库存；客户来源按登记来源汇总并可导出。继续沿用门店隔离与角色可见范围，不包含外网抓取或行业 BI。

跟进方式字典已接入主路径：`follow_method` 数据字典驱动写跟进与强制看电话表单；服务端校验并归一化旧值 `call`→`phone`；列表展示字典标签。字典为空时回退默认电话/微信/拜访/其他。

暂缓恢复与改接盘人已补齐：暂缓盘可恢复上架；店长/管理员恢复时可顺带更换本店接盘人，也可独立改接盘人。校验本店在职经纪/店长，通知新旧接盘人；已成交/已撤盘不可改。

编辑信息记「修改」跟进已落地：`house.update` / `customer.update` 在业务字段实际变更时自动写入 `follow_kind=modification` 跟进，内容为字段差异摘要；无变更不写。电话等敏感字段只记「已更新」，不落明文。该能力为本地留痕，不替代手工普通跟进。

客户来源字典已接入主路径：`customer_source` 数据字典驱动客源新建/编辑与列表筛选；服务端校验并归一化旧值如 `walk_in`→`门店到访`；列表与报表展示字典标签。字典为空时回退默认门店到访/转介/官网/来电/小程序/其他。来源可空；自定义字典启用后覆盖默认项。

改价跟进已接入主路径：房源价格实际变更时自动写入 `follow_kind=price_change`，与其它字段的「修改」跟进分离；无改价不写。跟进列表支持按对象类型/跟进类型筛选，并可按当前筛选导出 CSV；经营报表改价计数含自动改价跟进。

成交收款方式字典已接入主路径：`payment_method` 数据字典驱动佣金收款、退款与意向金登记；服务端校验并归一化别名如 `bank`→`transfer`；列表展示字典标签。字典为空时回退默认转账/现金/微信/支付宝/其他。自定义字典启用后覆盖默认项。简易收支、报销与租赁账单的收付方式仍用各自枚举，互不影响。

客源列表预算筛选已落地（M02-07 预算子集）：`customer.list` 支持 `budget_min`/`budget_max`，按客源预算区间与筛选区间相交匹配；未填预算的客源在启用预算筛选时排除；列表展示预算摘要。

运营深化已补充：房源、客源、跟进、带看按当前登录人数据权限导出；导出继续执行门店隔离、保密数据隔离和电话号码脱敏。经营报表增加跟进、改价跟进、带看及有效带看人员排行。界面偏好的主题、密度和水印已实际应用到客户端。

交易资料与过户已专项化：管理员可按买卖/租赁配置必传资料；成交附件按分类自动核销清单，并可启用“资料未齐禁止提交”。过户节点模板支持默认负责人角色，成交审批后自动生成，手工补齐保持幂等。原通用流程中的“交易资料清单”入口已移除，避免两套口径并存。

贷款按揭已专项化：成交贷款字段自动建立按揭记录，支持申请、审批、驳回、取消和放款；贷款过户节点只有在按揭审批后才能完成，完成后同步标记放款。原通用流程中的“贷款按揭”入口已移除。

成交投诉与更名已专项化：仅已审批成交可登记投诉；支持分类防重、店长分派调查、处理凭证必传后结案、驳回与发起人撤回。更名支持客户、业主或双方，提交前须上传证明材料，店长/管理员审批后写回客源姓名与房源业主姓名；财务可查看投诉但不可查看更名申请。原通用成交投诉、成交更名类型已移除。该能力区别于客户关怀域的客户投诉/诉讼，聚焦单笔成交纠纷与主体更名。

房源扩展已专项化：锁定/解锁必须填写原因并可设到期日，沿用 `houses.is_locked` 作为唯一锁定状态；合作盘支持内部员工或外部合作方、分成比例、结束原因和站内通知；视频/全景以本地路径登记并可归档；拍卖与独家/包销资料可启用并同步 `deal_mode`，结束独家/包销后恢复普通模式。原通用锁定盘、合作盘、媒体、拍卖和包销/独家代理类型已移除。该能力登记本地媒体路径，不提供在线转码或外网全景托管。

房源角色人已专项化：实勘、核验、摄影、户型、钥匙和委托角色支持同店指派与保护期；保护期内对应业务只允许角色人操作，管理员覆盖解除必须填写原因。实勘和验真会自动登记角色人，指派同步发送站内消息并记录审计。

业主委托已专项化：支持普通、独家和租赁托管委托的登记、续期、到期和终止；扫描附件必须挂接生效委托，登记同步建立委托角色保护。原通用流程中的“业主委托”入口已移除。

新房核心流程已专项化：支持本地项目启停、客户报备、保护期防重、到场确认、报备作废和过期重报；报备按本人/本店/全公司执行数据范围。分销公司支持本地登记、停用恢复、CSV 导出；销售报告须基于已到场报备，提交前强制上传网签合同扫描件，经店长/管理员审批后标记报备成交，财务登记结算且结算金额仅财务与管理员可见。通用新房记录中的项目、报备、到场、分销公司和销售报告类型已全部移除。该能力不包含分销小程序、外网渠道对接或厂商许可互联。

离职交接已专项化：店长或管理员可预览员工名下有效房源、客源、钥匙和房源角色，指定同店接收人后事务性完成资产转移；借出钥匙自动归还，未完成过户节点和业务记录同步转派，员工账号与全部会话即时停用。交接任务支持取消、消息通知和审计留痕，原通用离职记录类型已移除。

费用报销已专项化：员工可建立报销草稿并上传本地费用票据，提交后由同店店长或管理员审批，审批通过后由财务或管理员登记现金/银行付款及付款凭证。申请人不可审批或支付本人单据；报销按本人、本店和全公司执行数据范围，支持驳回修改、主动取消、消息和审计。原通用费用报销记录类型已移除。

资产台账与备查凭证已专项化：财务或管理员维护门店固定资产编码、分类、原值残值、保管人和存放位置，支持闲置与带原因处置；备查凭证按借贷平衡分录创建草稿，支持过账与作废，店长只读本店。原通用资产、会计凭证类型已移除。该能力是轻量资产台账和备查凭证，不提供会计科目体系、自动折旧、复式总账、结账或法定财务报表。

考勤请假已专项化：员工每日上下班打卡，系统按管理员配置的上下班时间和迟到宽限自动标记正常、迟到、早退或双重异常；店长和管理员可带原因修正本范围记录。请假支持年假、病假、事假和其他类型，自动计算小时并阻止待审批/已通过时段重叠；同店店长或管理员审批且禁止自审，员工可取消待审批申请。考勤和请假均按本人、本店、全公司范围隔离，并记录消息和审计。原通用考勤、请假记录类型已移除。

简易收支已专项化：财务或管理员可按门店登记收入、支出、发生时间、往来方、收付方式和可选关联成交，上传本地收支凭证；作废保留原记录并强制填写原因。店长只读本店，财务和管理员查看全公司，支持期间及方向筛选、收入/支出/结余汇总和 UTF-8 CSV 导出。原通用收入、支出类型已移除；该能力是门店现金账，不提供会计科目、复式记账、结转或法定财务报表。

岗位职级与员工调动已专项化：管理员配置职级代码、名称、级序和适用角色，员工定级必须记录原因和历史；店长可为本店其他员工发起不改变角色的跨店调动，管理员可发起角色变更并负责审批、按生效日执行。执行调动时，原店有效房源、客源、钥匙、房源角色、未完成过户节点和通用待办事务性交给指定原店员工，再切换员工门店/角色并清除旧会话；不兼容的新角色会解除当前职级。支持未来日期、重复任务拦截、消息和审计，原通用岗位职级、员工调动类型已移除。

招聘已专项化：店长可发布本店经纪人岗位，管理员可发布跨店经纪人、店长和财务岗位；候选人电话在进行中流程内公司级防重，支持新候选人、筛选、面试、Offer、入职、淘汰和退出状态机。进入面试前必须上传本地简历，淘汰必须填写原因；只有管理员能把 Offer 候选人转为真实员工账号，继承岗位门店、角色和候选人电话并执行密码策略，达到招聘人数后自动关闭岗位。招聘数据按本店/全公司隔离并记录审计，原通用招聘岗位和应聘记录类型已移除。

员工合同已专项化：支持劳动合同、保密协议和竞业协议，校验合同期限、试用期、签署日期、公司内合同编号及员工同类合同期限重叠。草稿合同登记签署日期并上传已签附件后才能启用；每次续签必须新增续签附件，支持到期刷新、续签恢复生效、带原因终止和完整事件履历。员工仅查看/上传本人合同，店长只读本店，管理员管理全公司；启用、续签和终止通过站内消息通知员工。原通用人事合同类型已移除。

薪酬已专项化：管理员维护员工基本工资、固定津贴、固定扣款和发薪银行档案并创建月度批次；财务从当前在职档案生成工资快照，可带原因调整津贴、奖金、扣款和税额，管理员审批后发布工资条，财务登记发薪流水。员工仅在审批后查看本人工资条，店长不能查看下属薪资，管理员和财务查看全公司；银行账号只返回尾号，工资调整、审批、发放均记录事件和审计并通知员工，支持 UTF-8 CSV。该能力不声称自动完成法定个税、社保或会计凭证核算，税额由财务录入。原通用薪酬条和薪酬发放类型已移除。

公告与知识库已专项化：管理员可面向全公司或指定门店创建公告、知识文章，店长只能管理本店内容；文档按草稿、已发布、已归档流转，支持分类、置顶、本地附件和每次修订的不可变版本留痕。员工只能查看范围内已发布内容，可提交幂等阅读回执并查看个人未读统计；公告发布向范围内员工发送站内消息，知识文章不强制广播。归档后普通员工不可见且内容不可修改，所有发布和归档操作进入审计。原通用公告、知识文章类型已移除。

办公协同已专项化：店长/管理员维护考试并发布，员工提交成绩且防重复参考；会议活动支持名额报名；流程会签按指定会签人并行确认并可驳回；票据支持申领、审批、发放与回收且禁止自审；工作总结可提交评阅；同事圈可发布并由店长隐藏；来电/去电登记并按本店客源电话或业主电话自动匹配。原通用考试、活动、会签、票据、总结、同事圈、来电类型已移除，通用业务套件模块列表已清空。该能力是本地办公协同，不提供在线监考、外呼线路或社交推送。

租赁托管已专项化：店长或管理员可把本地租赁房源登记为委托出租、集中式托管或自有物业，指定同店负责人并上传托管合同后启用。生效物业可建立期限不重叠的租约，校验租客、租期、月租、押金和付款周期，上传已签租约后启用并一次性生成完整周期账单；逾期账单自动刷新，管理员或财务只能足额确认收租，银行收款必须登记流水，管理员可带原因作废未收账单。租约终止保留已收账单并作废剩余账单，存在生效租约时禁止终止托管。维修和保洁工单支持同店指派、开始、完工凭证、实际费用、带原因取消和消息通知。托管负责人只看本人物业，店长看本店，管理员和财务看全公司；生命周期写入事件和审计。原通用托管物业、租约、账单、维修和保洁类型已移除。该能力是本地运营账，不代替法定会计、支付通道或租客端在线支付。

客户关怀已专项化：经纪人可对可见客户登记投诉，店长或管理员可登记诉讼并要求案号和法院；店长或管理员分派同店处理人并设定处理期限，处理人开始调查后须上传投诉凭证或诉讼文书才可登记解决方案，店长或管理员结案。发起人可撤回未分派投诉。满意度调查仅店长或管理员发起，客户回访可由经纪人发起但固定本人执行；未完成同类任务防重，超期自动刷新，调查完成必须填写 1 至 5 分满意度。客户电话按客源可见规则脱敏，财务不可访问；分派、结案和调查回访均发送站内消息并写入事件履历与审计。原通用投诉、诉讼、满意度问卷和客户回访类型已移除。

营销线索已专项化：店长或管理员可创建本地营销活动并启用/关闭；经纪人可录入本店线索，店长可分派同店负责人。线索按新建、跟进中、已确认、已转客、已流失、无效流转，公司内进行中同号防重，业务/商机黑名单拦截，转客后生成私客并继承负责人。在线委托支持本地登记、店长受理转线索或带原因驳回。电话按负责人/店长/管理员脱敏，财务不可访问；分派、转化和委托受理发送站内消息并写入事件与审计。原通用官网内容、在线委托、商机线索和营销活动类型已移除。该能力不包含外网平台群发、公众号/抖音官方接口或真实官网托管，仅本地承接获客结果。

积分分红已专项化：管理员维护积分规则；店长录入本店积分后由管理员审批，管理员可直接入账。员工仅看本人积分余额，店长看本店，管理员看全公司。业绩目标支持门店或员工维度的佣金/成交单数，并按已审批成交自动计算完成进度。财务或管理员可按门店当月已审批佣金和设定比例生成店长管理奖并登记发放；管理员可按当月有效积分创建利润分红批次，财务登记发放后员工仅看本人份额。消息、事件和审计完整留痕。原通用积分、管理奖、利润分红和业绩目标类型已移除；该能力不代替完整薪酬总账或自动税务核算。
